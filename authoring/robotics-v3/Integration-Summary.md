`packages/shared-foundations-learning-edition-01/INTEGRATION.md` and

## Dataset identity and ID mapping

The content was applied to the **dedicated robotics v3 map only**. The original Skill Solar System
atlas was not opened for writing, not patched, and not read for answers.

| | |

The proposed `rob3:` ids were the ones actually implemented, so the mapping is one to one and no
rename was needed. Identity was still checked per lesson rather than taken on trust: planning id,
runtime id, name, required prerequisites and the `node_contract_sha256` fingerprint must all agree
with the reviewed specification before a lesson is applied. The fingerprint is reproduced byte for
byte from Python's `json.dumps(..., sort_keys=True)`, spacing and `\uXXXX` escapes included
(`pythonJson` in `authoring/robotics-v3/lessons.mjs`).

## Field mapping

The verbatim lesson record is stored on each node as `lesson`, so every authored field travels with
the export, including the ones the interface does not render yet (`branch`, `dependency_depth`,
`node_contract_sha256`, `content_status`, `proficiency_write`). A reader-facing summary is stored as
`lessonCard`, and the two card fields the app already had are filled from the lesson:

| Lesson field | Where it goes |
| --- | --- |
| `details` | `node.details` — the explanation and worked example, two paragraphs |
| `placement_note` | `node.placementNote` |
| `explanation`, `worked_example` | card section “Explanation and worked example” |
| `why_it_matters` | card section “Why this matters and what it builds on”, beside prerequisites read from the map's own edges |
| `practice` | card section “Practice question”, answer behind **Show answer** |
| `boundary_case` | card section “Boundary or misconception check”, answer behind its own **Show answer** |
| `full_demonstration`, `assessment_contract` | card section “Full demonstration and evidence”, rendered as labelled text |
| `references`, `required_future_work` | card section “References and remaining learning work” |
| `practice_mode`, `assessment_contract.mode` | named in the card, distinguishing an introductory exercise from a simulated result and from physical or supervised work |
| `instructional_scope` | shown once under the card's status line |
| everything else | kept verbatim in `node.lesson` |

Edition 01 predates the per-lesson `full_demonstration` and `assessment_contract` fields. Both were
taken from the reviewed specification, which edition 02 copies verbatim (checked: all 116 of edition
02's copies are identical to the specification's). No demonstration text was invented.

`assessment_contract.task` repeats the demonstration wording in all 193 entries, so the card shows
it once rather than twice.

## Limitations

- These are introductory cards. They are not a complete course, an exhaustive question bank, or
  evidence of practical mastery. Every entry keeps its larger demonstration requirement.
- 187 assessable entries still have no introductory lesson. One roadmap entry is not assessed.
- Nothing in the application writes a proficiency answer by itself. Opening a card, revealing an
  answer or reading an exercise changes nothing; the app has no “mark exercise complete” control to
  attach an answer to, and none was added. Only the existing Yes / No / Clear controls and the
  guided review write answers.
- The runnable teaching simulation (`joint_lab.py`) stays an offline exercise. The app has no code
  runner, and the simulation was not wired to anything.
- The map title now states the authored and pending counts. Guided-review sessions are keyed on the
  title plus the node set, so a session saved against the old preview title restarts. Review *order*
  is unchanged.
- The export is 2.2 MB. It opens well within the app's 10 MB limit, and Save, reopen and the draft
  cache were all exercised at that size.
- Not tested: hardware, wiring, firmware, physical measurement, or any claim that a learner has
  demonstrated anything. Content status is not proficiency.
- Pre-existing and unrelated: `node tests/review-e2e.mjs` with `SSS_ATLAS` set times out when it
  opens the 5.4 MB atlas at the end of its long session. The same file opens correctly in a fresh
  session, and the failure reproduces identically on the commit before this work.
